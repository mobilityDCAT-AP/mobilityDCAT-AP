Usage note

According to [[FOAF]], an Agent may be of a type of a person (via sub-class foaf:Person), an organisation (via sub-class foaf:Organization), or a group (via sub-class foaf:Group).

For mobility data portals, it is expected that organisations are the main data actors, so the type organisation is preferred. In such case, the use of the Organization Ontology is recommended.

If a person is mentioned as an agent, he or she should be attributed to an organisation via the property org:memberOf, and, additionally, attributed with the personal name via properties foaf:firstName and foaf:surname.

The agent might be populated with the same information as for a kind, see class vcard:Kind.

When providing agent information, data publishers should prioritize organizational information over personal details. The exposure of personal information, such as a personal name and email address, may be restricted to the public. Instead, there might be an anonymous contact channel, e.g. a contact button on the GUI that triggers an email to the agent. See .

See also the Wiki page with more recommendations on the usage of organisational and personal information.

Properties

For this entity the following properties are defined: address, affiliation, email, first name, name, phone, surname, type, URL.
